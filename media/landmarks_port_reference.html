YARP Port Documentation

landmarks:o

Per-face detail port published by VisionAnalyzer every module tick (~50 ms). Carries a structured bottle with 13 fields of identity, spatial, pose, and behavioral data for every face detected in the current frame.

yarp::Port (blocking write)
Bottle → list of face sub-bottles
50 ms default period
01

Overview

Context

landmarks:o is one of four output ports on the VisionAnalyzer module (features:o, landmarks:o, targetBox:o, faces_view:o). While features:o publishes a single scene-level summary (total faces, motion, light, mutual-gaze count), landmarks:o goes deeper: it publishes one nested sub-bottle per individual face, carrying every computed attribute for that person.

The port is only written when at least one subscriber is connected. The module checks landmarks_port.getOutputCount() > 0 each tick and skips the entire perception pipeline if no port is connected — saving significant CPU.

Reading the bottle downstream Iterate over the top-level list. Each element is a nested bottle representing one face. Fields are interleaved key-value pairs: a string key followed by its value (or a nested list for bbox and gaze_direction). There is no face-count header; the number of sub-bottles equals the number of tracked faces in the frame.

Association step _associate_face_observations() performs one-to-one greedy matching between MediaPipe faces and YOLO-tracked bboxes using a score = (normalised centre-distance) − (bbox overlap ratio × 0.5), with a 0.75 penalty if the MediaPipe centroid falls outside the YOLO box. Match is rejected if: centroid is outside the box AND distance exceeds max(max_face_match_distance=100px, 0.6 × max(w,h)) AND overlap ratio < 0.15.

The six anatomical anchor points used for solvePnP are MediaPipe landmark IDs: 1 (nose tip), 199 (chin), 33 (left eye outer), 263 (right eye outer), 61 (left mouth corner), 291 (right mouth corner). The corresponding 3-D reference coordinates are a generic face model in millimetres (nose tip at origin). The camera matrix is constructed assuming focal_length = image_width (no lens calibration).

03

Bottle Structure

Schema

The top-level landmarks_btl is a flat YARP Bottle. Each face is appended as a nested sub-bottle via landmarks_btl.addList().read(face_btl). Fields within each sub-bottle are sequential key-value pairs (string key, typed value).

landmarks_btl // top-level Bottle, one element per face │ ├─ [face 0] face_btl // nested list sub-bottle │ ├─ "face_id" → string // identity name or "unknown" │ ├─ "track_id" → int32 // ByteTrack persistent ID │ ├─ ["bbox" x y w h] // nested list, float64, pixels │ ├─ "zone" → string // horizontal zone enum │ ├─ "distance" → string // proximity enum │ ├─ ["gaze_direction" dx dy dz] // nested list, float64, unit vector │ ├─ "pitch" → float64 // degrees, up/down │ ├─ "yaw" → float64 // degrees, left/right │ ├─ "roll" → float64 // degrees, lateral tilt │ ├─ "cos_angle" → float64 // −1 (away) → 1 (facing cam) │ ├─ "attention" → string // gaze state label │ ├─ "is_talking" → int32 // 0 or 1 │ └─ "time_in_view" → float64 // seconds since first seen │ ├─ [face 1] face_btl // same schema … │ └─ [face N-1] face_btl
Nested list encoding note bbox and gaze_direction are both written as nested Bottles via face_btl.addList(). The first element of each nested list is a string key ("bbox" / "gaze_direction"), followed by the numeric values. Do not confuse these with the flat string-then-scalar pairs used for all other fields.

Identity & Tracking

2 fields

Who is this face and how consistently is it tracked across frames?

Identity & Tracking 2 fields
face_id
string YOLO crop
addString("face_id")
addString(face_data['face_id'])
Identity label produced by the face_recognition library, which compares a 128-D embedding of the YOLO-cropped face against a database of known encodings loaded from faces/ at startup. Uses a cosine-distance tolerance of id_tolerance=0.62.

A sticky mechanism caches the last confirmed identity for up to identity_sticky_sec seconds (default 1.5 s). If a face drops to unknown after being identified, the cached name is re-used while up to unknown_retry_max_attempts (default 3) background retries fire at intervals of unknown_retry_interval_sec (default 1–2 s). Thread-safe: all writes use _face_identity_lock.
Possible values
"alice" any name matching a file in the faces/ folder
"unknown" face detected but no match within tolerance; retries in progress
"unmatched" MediaPipe saw a face but no YOLO bbox was associated (scenario 2)
track_id
int32 ByteTrack
addString("track_id")
addInt32(face_data['track_id'])
Persistent integer identifier assigned by supervision.ByteTrack. Survives brief occlusions up to a lost_track_buffer=120 frame window (~6 s at 20 Hz). Once lost beyond that buffer, the face reappears with a new ID.

All per-face state (mouth history, first-seen timestamps, identity cache) is keyed by this ID. Downstream modules should use track_id as the primary key for any per-person state machine.
Possible values
≥ 0 valid persistent tracker ID (monotonically increasing)
−1 MediaPipe-only face (no YOLO/ByteTrack match; scenario 2)

Spatial Position

3 fields

Where in the image is this face, and how close is the person?

Spatial Position 3 fields
bbox
nested list YOLO
bbox_btl = addList()
addString("bbox")
addFloat64(x) y w h
Bounding box of the detected face in pixel coordinates, using a top-left origin (image convention). Packed as a nested Bottle list: first element is the string key "bbox", followed by four float64 values.

The box has been expanded 10% per side from YOLO's raw output to give downstream face-crop operations better context (forehead, chin margins). Clamped to image boundaries after expansion. Resolves to 0 0 0 0 in the MediaPipe-only fallback scenario.
Encoding
x left edge of box in pixels (float64)
y top edge of box in pixels (float64)
w width in pixels (float64)
h height in pixels (float64)
zone
string computed
addString("zone")
addString(zone)
Horizontal zone of the face within the frame. Computed from the bounding-box centre (cx = x + w/2), normalised to [0, 1] over default_width = 640 px. Useful for coarse spatial attention commands (e.g. "face is on the left side, turn camera right").
Thresholds (cx_n = cx / 640)
"FAR_LEFT"cx_n < 0.20
"LEFT"0.20 ≤ cx_n < 0.40
"CENTER"0.40 ≤ cx_n < 0.60
"RIGHT"0.60 ≤ cx_n < 0.80
"FAR_RIGHT"cx_n ≥ 0.80
"UNKNOWN"no YOLO match (scenario 2 or 3)
distance
string computed
addString("distance")
addString(distance)
Proximity estimate based on the height of the bounding box relative to the frame height (h_norm = h / 480). No metric calibration is performed — this is a pure image-space heuristic that assumes a fixed camera focal length and typical face size. Works reasonably for front-facing HRI scenarios but will degrade with wide-angle optics or unusually sized subjects.
Thresholds (h_norm = h / 480)
"SO_CLOSE"h_norm > 0.40 — face fills >40% of frame height
"CLOSE"0.20 < h_norm ≤ 0.40
"FAR"0.10 < h_norm ≤ 0.20
"VERY_FAR"h_norm ≤ 0.10 — face fills <10% of frame height
"UNKNOWN"no YOLO bbox available

Head Pose & Gaze Direction

5 fields

Where is the face pointing in 3-D camera space? All five fields are derived from the same PnP solve on MediaPipe landmarks.

Head Pose & Gaze 5 fields
gaze_direction
nested list MediaPipe
gaze_btl = addList()
addString("gaze_direction")
addFloat64(dx) dy dz
The face's nose-forward unit vector expressed in camera coordinates. Computed as R @ [0, 0, −1], where R is the 3×3 rotation matrix from cv2.Rodrigues(rvec) (output of solvePnP).

Camera convention: +X right, +Y down, +Z into the scene (away from camera). A face looking directly at the camera therefore yields approximately [0, 0, 1] (before sign flip of the face-forward axis). Packed as a nested Bottle list: key "gaze_direction" followed by three float64 values.
Components
dxrightward component (float64)
dydownward component (float64)
dzinto-scene component (float64)
[0,0,0]sentinel — no MediaPipe match for this face
pitch
float64 MediaPipe
addString("pitch")
addFloat64(float(pitch))
Vertical head tilt angle in degrees. Extracted as angles[0] from cv2.RQDecomp3x3(rmat). Positive pitch = head tilted upward; negative = tilted downward.
Range & meaning
> 0°chin up / looking upward
≈ 0°level gaze
< 0°chin down / looking downward
0.0sentinel — no MediaPipe match
yaw
float64 MediaPipe
addString("yaw")
addFloat64(float(yaw))
Horizontal head turn angle in degrees. Extracted as angles[1] from cv2.RQDecomp3x3. In OpenCV camera convention, positive yaw means the face is turned to the right (from the camera's perspective).
Range & meaning
> 0°face turned right (camera perspective)
≈ 0°face forward
< 0°face turned left
0.0sentinel — no MediaPipe match

addString("roll")
addFloat64(float(roll))
Lateral head tilt (in-plane rotation) in degrees. Extracted as angles[2]. Non-zero when the person tilts their head sideways — common in listening posture or expressions of curiosity. Useful for affect recognition.
Range & meaning
> 0°head tilted to one side
≈ 0°head upright
0.0sentinel — no MediaPipe match
cos_angle
float64 computed
addString("cos_angle")
addFloat64(float(cos_angle))
Cosine similarity between the face's forward vector (gaze_direction) and the camera's look-at axis [0, 0, 1]. This is the primary scalar driving the attention classification and the global MutualGaze counter published on features:o.

A value of 1.0 means the face is pointing exactly at the camera. A value of 0.0 means the face is perpendicular to the camera axis. Negative values indicate the back of the head is facing the camera.
Range & decision thresholds
> 0.90→ MUTUAL_GAZE; increments MutualGaze counter
0.70 – 0.90→ NEAR_GAZE; near eye contact
≤ 0.70→ AWAY; not looking at camera
0.0sentinel — no MediaPipe match
05d

Behavioral State

3 fields

What is the person doing? These are the highest-level semantic outputs of the module.

Behavioral State 3 fields
attention
string computed
addString("attention")
addString(attention)
Gaze-state classification derived entirely from cos_angle using two fixed thresholds. When a face is classified as MUTUAL_GAZE, the module also increments the env_dict["MutualGaze"] counter, which is published separately on features:o as a scene-level count of how many people are simultaneously engaged in eye contact.
States
"MUTUAL_GAZE" cos_angle > 0.90 — direct eye contact
"NEAR_GAZE" cos_angle > 0.70 — face directed near camera
"AWAY" cos_angle ≤ 0.70 — not looking at camera
"UNKNOWN" YOLO-only face — no MediaPipe landmarks available
is_talking
int32 MediaPipe
addString("is_talking")
addInt32(is_talking)
Binary lip-motion detector. Tracks the distance between MediaPipe landmark 13 (upper inner lip) and 14 (lower inner lip) across a rolling buffer of the last mouth_buffer_size = 10 frames.

The raw distance is scale-normalised by the matched face's bbox height (mouth_open = raw / (h / 480)), making detection robust to varying face sizes. When at least 3 frames are in the buffer, talking is flagged if std(buffer) > talking_threshold (default 0.012). The standard deviation (not mean) is used — this detects motion, not mouth openness, preventing false positives from people who speak with a wide-open mouth.

The buffer is keyed by track_id and cleared when a track is absent for more than 1 second. Requires at least 3 frames of history before it can fire (~150 ms lag).
Values
1talking detected — mouth motion std > 0.012
0silent / insufficient history / no MediaPipe match
time_in_view
float64 computed
addString("time_in_view")
addFloat64(float(time_in_view))
Wall-clock elapsed time in seconds from when this track_id was first seen (first_seen_track[track_id]) to the current frame. Set using time.time(), so it is real-world seconds, not frame count.

The timer resets when a track_id has been absent for more than 1 second (cleanup runs at end of each detect_mutual_gaze call). If a face briefly disappears and is re-assigned the same track_id by ByteTrack (within the lost-track buffer), the timer keeps running.

Useful for salience scoring — a face that has been present for 60 seconds likely warrants more attention than one that just appeared. Also useful for engagement metrics in HRI logs.
Range
0.0 → ∞seconds since first detection of this track_id
0.0unmatched face (MediaPipe-only scenario)

Thresholds & Configuration

Tunable

All parameters below can be set via the YARP ResourceFinder configuration file or command-line flags passed to the module. Defaults are the in-code values.

RF Parameter Default Effect on landmarks:o
conf_threshold 0.7 Minimum YOLO detection confidence. Faces below this are dropped before ByteTrack. Affects number of sub-bottles published.
id_tolerance 0.62 Cosine distance threshold for face_recognition match. Lower = stricter matching; more "unknown" results. Higher = more false positives.
identity_sticky_sec 1.5 How long a confirmed identity is cached in face_id after the face goes unrecognised again.
unknown_retry_interval_sec 1.0 – 2.0 Gap between face_recognition retry attempts for an "unknown" face before giving up.
unknown_retry_max_attempts 3 Maximum number of retries before a face is permanently labelled "unknown" this session.
talking_threshold 0.012 Std-dev threshold for is_talking. Increase to reduce false positives (less sensitive). Decrease to catch subtle lip movements.
mouth_buffer_size 10 frames Rolling window size for is_talking. Larger = more stable but higher latency. At 20 Hz: 10 frames ≈ 500 ms lag.
max_face_match_distance 100 px Hard limit for MediaPipe↔YOLO centroid matching. Faces whose centroids are farther apart than this (and have <15% overlap) are not matched.
mutual_gaze_threshold 10° Defined in code but not directly used in landmarks:o; the active decision uses cos_angle thresholds (0.90 / 0.70) from detect_mutual_gaze().
rate 0.05 s Module update period (getPeriod). Directly controls publication frequency of the landmarks bottle.
Camera matrix approximation The PnP solve uses focal_length = image_width (640 px by default) as both fx and fy, with principal point at the image centre. No lens distortion is modelled (dist_coeffs = zeros(4,1)). This means pitch / yaw / roll and gaze_direction are computed under a simplified pin-hole model. For precise head-pose estimation, replace with a calibrated camera matrix via a configuration parameter.
